# DelegateCall

## Introduction

A **delegate call** lets a contract execute code from another contract **while keeping its own context**. That means storage, `msg.sender`, and `msg.value` all remain those of the **calling** contract—so state changes affect the caller, and the original sender/value are preserved.

In Stylus, you can delegate-call in two ways:

* **Low-level `delegate_call` function** — unsafe, bytes-in/bytes-out.
* **`RawCall` with `new_delegate()`** — unsafe, fluent builder for advanced control.

> ⚠️ **Safety**: Delegate calls are powerful and dangerous. The callee can arbitrarily mutate your storage or spend ETH. Even though caches are cleared for safety, this does **not** prevent harmful behavior; use only with trusted code.

---

## Delegate calls in Stylus

### 1) Using the low-level `delegate_call` function

`delegate_call` is a low-level, **unsafe** operation (similar to `call`/`static_call`) that requires you to supply the VM handle and a **mutating** call context. You pass the target address and raw calldata, receive raw return bytes, and handle errors yourself.

```rust
// low-level delegate call (unsafe)
pub fn low_level_delegate_call(
    &mut self,
    calldata: Bytes,
    target: Address,
) -> Result<Vec<u8>, DelegateCallErrors> {
    unsafe {
        // Build a mutating context; delegate calls always mutate the caller’s storage
        let config = Call::new_mutating(self);

        // Perform the delegate call: VM handle + config + target + calldata
        let result = delegate_call(self.vm(), config, target, &calldata)
            .map_err(|_| DelegateCallErrors::DelegateCallFailed(DelegateCallFailed {}))?;

        Ok(result)
    }
}
```

**Why unsafe?** You’re executing untrusted code in **your** storage context; the callee can change anything. Although caches are cleared, that doesn’t stop malicious behavior.

---

### 2) Using `RawCall` with `new_delegate()`

`RawCall` provides a fluent, bytes-in/bytes-out builder for unsafe calls. Use it when you need granular control (gas limits, return-data windows, cache flushing).

```rust
pub fn raw_delegate_call(
    &mut self,
    calldata: Vec<u8>,
    target: Address,
) -> Result<Vec<u8>, Vec<u8>> {
    let data = unsafe {
        RawCall::new_delegate(self.vm())   // configure a delegate call bound to this VM
            .gas(2100)                     // supply 2100 gas
            .limit_return_data(0, 32)      // only read the first 32 bytes back
            .flush_storage_cache()         // flush storage cache before the call
            .call(target, &calldata)?      // execute
    };
    Ok(data)
}
```

> `RawCall` exposes helpers like `.gas(...)`, `.limit_return_data(...)`, and cache controls. Use it sparingly: it’s still unsafe and untyped. (See `RawCall` docs for the delegate builder and options.) ([Docs.rs][3])

---

## Summary

* **Delegate calls keep caller context** (storage, `msg.sender`, `msg.value`) and thus can **mutate the caller’s state**.
* **Low-level `delegate_call`**: unsafe, requires VM handle + mutating `Call` context; returns raw bytes; you must handle errors.
* **`RawCall::new_delegate(...)`**: unsafe, fluent builder with gas/return-data/cache controls.
* **Trust is mandatory**: clearing caches doesn’t make delegate calls safe. Only delegatecall to trusted code. ([Arbitrum Docs][1])
